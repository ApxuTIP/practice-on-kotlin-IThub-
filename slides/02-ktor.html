Зачем

Память vs база

mutableList

Живёт, пока жив процесс. Удобно отладить маршруты. Для API — мало.

Postgres

Живёт в отдельном процессе. Сервер упал — записи на месте. Это уже сервис.

11

Docker

База — одна команда

docker run --name ithub-pg -d \
  -e POSTGRES_PASSWORD=pass \
  -e POSTGRES_DB=shop \
  -p 5432:5432 \
  postgres:16

Приложение на 8080, база на 5432. Не ставим Postgres на хост руками.

12

Exposed

Что такое Exposed

  • Библиотека JetBrains. SQL из Kotlin, не Hibernate и не «магия JPA».
  • Таблица — объект. Строка — код в transaction { ... }.
  • Нужны: exposed-core, exposed-jdbc, драйвер postgresql.
13

Exposed

Таблица = объект

object Products : Table() {
    val id = integer("id").autoIncrement()
    val name = varchar("name", 100)
    val price = integer("price")
    override val primaryKey = PrimaryKey(id)
}

03

Часть 3. Вход

Пароль в хеше. Логин выдаёт билет. Билет — в заголовке.

03

BCrypt

Пароль в базу текстом нельзя

  • BCrypt из пароля делает длинную строку. Обратно в пароль её не превратить.
  • При логине: берём введённый пароль, считаем хеш, сравниваем с тем, что в базе.
  • Совпало — человек свой. Нет — 401. Сам пароль мы не храним и не логируем.
17

JWT

Токен — билет на сеанс

  • Сервер подписывает строку секретом: кто ты и до какого часа.
  • Клиент кладёт её в Authorization: Bearer … на каждый запрос.
  • Подпись не бьётся или билета нет — 401. Пароль больше не шлём.
18

JWT

Как получают токен

POST /register   { "email": "a@b.c", "password": "1234" }
POST /login      { "email": "a@b.c", "password": "1234" }
                 → { "token": "eyJhbGciOi…" }

GET /items
Authorization: Bearer eyJhbGciOi…

/register и /login без билета. Остальное — только с ним.

19

JWT

Что делает сервер

/login

Нашёл пользователя, BCrypt совпал — собрал JWT с email внутри, отдал строку.

остальные маршруты

Плагин jwt проверяет подпись. Ок — пускает в handler. Нет — даже не заходит в код списка.

20

HTTPie

Токен в коллекции

  • Запрос Login. Из ответа копируем token.
  • В остальных запросах заголовок Authorization, значение Bearer и токен.
  • Без заголовка тот же GET /items должен дать 401 — так и проверяем.
